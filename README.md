# Inferry

> **v2.0.0**：原 **CanvasHelper** 更名为 **Inferry**。功能与 1.3.4 基本一致，变化集中在产品名、数据目录和发布资产名。

Inferry 是一个面向 Windows 的 **Canvas 课程同步与学习辅助工具**。它用你自己的浏览器登录态读取学校的 Canvas，把课程文件按你已有的目录习惯归档到本地，并把作业截止时间写进 [DeskBox](https://github.com/Tianyu199509/DeskBox) 的待办小组件。

- 平台：Windows 10 / 11
- 运行环境：绿色版（压缩包解压即用，无需 Python）或 Python 3.9 ~ 3.14 源码运行
- 运行时依赖：`playwright`（驱动系统 Edge / Chromium）、`tzdata`（IANA 时区库）；界面为 Python 标准库 tkinter，无其他第三方 GUI 依赖
- 许可：MIT

## 主要功能

### 1. 登录：复用自己的浏览器会话

- 默认驱动系统自带的 **Microsoft Edge**，不额外下载任何浏览器；Edge 缺失或被组策略禁用时，回退到 Playwright 自带的 Chromium（设置页「安装 Chromium」或 `inferry install-browser`，约 150 MB）。
- 登录完全走学校自己的 SSO / 2FA 页面，程序只负责在登录成功后保存会话；之后以无窗口方式复用，不必每次输入密码。
- 会话过期时会打开登录窗口等待你完成登录；后台（计划任务）场景可配置是否弹窗。
- 首次运行没配置站点地址时，会先弹出「选择院校」：内置 126 所已核实院校，可搜索、按地区筛选、手填地址，也能在线合并 Instructure 官方院校目录（30 天缓存，失败自动降级）。

### 2. 内容采集：多路来源，互相兜底

同一门课在不同老师手里用法差异极大，因此以下来源全部采集，单一路径失败不影响其余：

- **模块条目**（文件、页面、作业、讨论）；
- **页面正文**（页面列表接口被关掉时，改用页面 show 接口或抓页面源码，从正文里挖出附件与链接）；
- **作业描述**；
- **公告与讨论帖**（含回帖）；
- **课程文件索引**（学生账号常被禁止列出全课文件，此时自动跳过而不中断）。

补充行为：

- 隐藏 / 锁定文件会跳过；
- 讨论区里的 Colab、GitHub 链接会转成可直接下载的直链（`github.com/.../blob/...` → `raw.githubusercontent.com`；个人 Drive 型 Colab 链接 → 直链下载），链接没有文件名时用帖子标题命名；
- 讨论帖本体保存为 HTML 快照，作为私有仓库/未公开分享下载失败时的兜底。

### 3. 归档：跟随你已有的目录习惯

- **课程代码通用识别**：字母前缀 + 3~5 位数字（`CS5187`、`MATH 101`、`ECON2201`），自动剥掉学期数字前缀（`202609CS5187` → `CS5187`）；课程代码形态特殊的学校可用 `course_code_pattern` 写自定义正则。
- **课程文件夹自动匹配**：比较时忽略空格、连字符、下划线的差异（`MATH 101` 与 `MATH101` 视为同一门课），匹配不到才按 `课程代码 - 课程名` 新建，避免每次同步都多出一个重复文件夹。
- **六类目录**（以磁盘上真实存在的 `数字.` 前缀目录为准）：

  | 前缀 | 逻辑分类 | 默认目录名 |
  | --- | --- | --- |
  | `1.` | 讲义 | `1.Lecture session` |
  | `2.` | 习题 / 上机 | `2.Tutorial session` |
  | `3.` | 作业 | `3.Assignments` |
  | `4.` | 项目 | `4.Projects` |
  | `5.` | 参考书 / 阅读 | `5.Books` |
  | `6.` | 其他 | `6.Others` |

- **镜像 Canvas 文件夹层级**：真实存在的 Canvas 文件夹会映射成子目录；讲义按「章/周」编号归入 `Lecture3` / `Week2` 这类子目录，并**跟随本地既有命名样式**（本地有 `Lecture1` 就统一成 `Lecture{n}`）；识别不到章节号的散件（`data.zip`）保持平铺。
- **只增不删、不重复下载**：已存在的文件按「归一化文件名 + 大小」判断（`0.Introduction.pptx` 与 `Introduction.pptx`、`x.pptx` 与 `x (1).pptx` 视为同一份），同名不同内容自动加 `(1)`；同步记录写入 `state.json`，下次只补新增与变更。
- **压缩包智能处理**：含讲义/代码（`.ipynb` `.py` `.pdf` `.pptx` 等）判为**内容包**自动解压；包名命中 `data` / `train` / `mnist` 等词，或包内只有数据文件则判为**数据包**原样保留。解压拒绝 `zip-slip`、跳过 `__MACOSX` / `._*` / `.DS_Store`、单包上限 2 GiB、同名同大小幂等跳过。`.rar` / `.7z` 需要外部工具，不作处理。

### 4. 待办：写进 DeskBox

- 作业与测验的截止时间 → DeskBox 待办：标题为「课程代码 · 作业名」，备注带原文摘要与「打开」链接，相关附件以本地链接方式挂上。
- 自动跳过已过期以及一年以后的条目；未配置 DeskBox 时其余功能照常。
- **课程配色**：8 种颜色按课程自动分配，也可在设置页逐课编辑；自建待办可用单独的颜色（默认粉色），避免与课程待办混色。
- **去重与状态**：已存在的不重复添加；已完成的不会「删掉又冒出来」；Canvas 上截止时间改动过的视为重开并重新提醒；已有完成记录的同名同截止重复项会被清理。
- **按截止时间排序**：写入时重写 `sortOrder`（会覆盖手动拖动顺序，可在设置页关闭）。
- **写入方式**：先把合并结果写成 `todo.json.new` 副本 → 关闭 DeskBox → 原子替换 → 立即重启，停机约 1 秒。后台同步可三选一：排队（默认，下次打开 Inferry 时补写）、立即重启 DeskBox、跳过。

### 5. 学习辅助

- **通知 / 公告聚合**：课程公告 + Canvas 活动流，按时间倒序，未读条目有标记；已读状态只记录键值，公告正文不落盘。
- **成绩追踪**：同步时把总评与已出分项目写/刷新到每门课的 `GradeNeed.txt`，界面「成绩」页可直接查看。
- **日历导出**：生成 `canvas-deadlines.ics`，每个截止时间一条日程，自带提前 1 天的提醒，可导入 Outlook / Google / Apple 日历。
- **每周摘要**：每门课生成 `本周摘要-YYYY-Www.md`，包含本周新增文件、最近公告、未来 7 天截止、已出分项目。
- **讲义整理**：把讲义分类目录根部散落的 `Lecture3a.pdf` 之类文件移进对应章节目录；先预览方案，`--apply` 才真正移动；只移动不删除，并同步更新 `state.json` 里的路径。

### 6. 自动化

- **Windows 计划任务**：每日自动同步、每周自动摘要；命令不经过控制台程序，不会每天闪黑框；程序被移动过位置后，启动时会按当前位置自动重建任务。
- **静默失败防护**：后台同步发现登录过期时，会把「待重新登录」写进状态，GUI 下次打开时在顶栏醒目提示；命令行退出码 `2` 专门表示登录过期，与一般错误（`1`）区分。

### 7. 版本更新、清理与卸载

- **更新检查**：数据源是 GitHub Releases，默认 24 小时最多联网检查一次（可关、可改间隔、可选择是否包含预发布版本），离线或接口异常一律静默降级，不影响正常使用。
- **一键更新（仅 exe 版）**：下载 win64 zip → 解压 → 生成替换脚本 → 退出后自动换上新版本；源码运行时只打开下载页，不动你的工作目录。
- **一键清理缓存**：默认只清可再生内容（同步状态、已读标记、导出日历、日志、浏览器缓存），登录态与排队待办需要显式勾选，并先显示每项占用体积。
- **一键卸载**：`uninstall.bat` / `inferry uninstall`，删除程序目录、使用数据、计划任务与桌面快捷方式；**不动课程文件夹，也不动 DeskBox 里的待办**。

### 8. 双入口：界面与命令行

- 图形界面分五个标签页：**课程同步**、**待办（DeskBox）**、**通知 / 公告**、**成绩**、**设置**；耗时操作在后台线程执行，带进度条与滚动日志。
- 同一套能力都有命令行入口，便于脚本、计划任务与无窗口环境（见下节命令表）。

## Quick start

### 方式一：下载即用（推荐）

1. 到 Releases 页下载最新的 `Inferry-v2.0.0-win64.zip`。
2. **解压到可写目录**（例如 `D:\Apps\`）。不要放在 `C:\Program Files`，也不要直接在压缩包里双击运行——程序以后要「一键更新」，需要能覆盖自己所在的目录。
3. 如果 zip 的「属性」里有「解除锁定」，先勾选并应用，**再**解压；否则 Windows 可能拦住压缩包内自带的 `node.exe`。
4. 双击 `Inferry\Inferry.exe` 启动。首次运行若出现「Windows 已保护你的电脑」，点「更多信息」→「仍要运行」。
5. 首次配置流程：
   1. 「选择院校」→ 搜索并选中你的学校（不在清单里就手填域名，例如 `canvas.example.edu`）；
   2. 在弹出的浏览器窗口里完成学校的 SSO / 2FA 登录，成功后窗口自动关闭；
   3. 回到「课程同步」页，双击课程行勾选要同步的课程；
   4. 打开「设置」确认**课程根目录**（默认 `%USERPROFILE%\CanvasCourses`，可改成你现有的课程文件夹）；
   5. 点「预览归档方案」看清将下载/更新什么、落到哪里，确认无误后点「开始同步」。
6. 待办联动：若本机装有 DeskBox，程序会自动发现它的 `todo.json` 与 `DeskBox.exe`；没有或猜错了，在设置页用「浏览…」手选。之后到「待办（DeskBox）」页点「读取截止时间」→「写入 DeskBox」。
7. 想让它自己跑：设置页勾选「启用每日自动同步」（默认 08:30），必要时勾选「每周生成学习摘要」；点「保存设置」后计划任务即被创建。
8. 建议顺手在设置页点「创建桌面快捷方式」，以后从桌面启动。

### 方式二：源码运行

```powershell
git clone https://github.com/Botherain/Inferry.git
cd Inferry

python -m pip install -e ".[dev]"   # 只跑程序：python -m pip install .
python -m inferry                   # 不带参数 = 启动图形界面
```

- 也可以 `pip install .` 后直接运行 `inferry`（命令行）或 `inferry-gui`（无控制台启动器）。
- 依赖安装完成后，双击仓库里的 `Inferry.pyw` 同样可以无控制台启动。
- Python 3.9 会自动解析到仍支持 3.9 的 Playwright 版本，无需手动降级。
- 更新依赖或换机器后，`python -m inferry --selftest` 可快速检查打包/安装是否完整（退出码 0 为正常）。

### 命令行速查

| 命令 | 作用 |
| --- | --- |
| `inferry` / `inferry gui` | 启动图形界面（默认） |

| `inferry flush` | 把后台排队的待办补写进 DeskBox |
| `inferry clean [--dry] [--login] [--pending] [--todos]` | 清理缓存；`--dry` 先预览 |

### 数据存放位置

程序与数据分离：换安装位置、换盘符、删程序目录都不影响配置与登录态。

| 路径 | 内容 |
| --- | --- |
| `%LOCALAPPDATA%\Inferry\config.json` | 设置（站点、时区、目录、待办配色、计划任务等） |
| `%LOCALAPPDATA%\Inferry\state.json` | 同步记录、已读标记、已完成待办索引 |
| `%LOCALAPPDATA%\Inferry\pending_todos.json` | 后台同步排队的待办 |
| `%LOCALAPPDATA%\Inferry\session.json`、`profile\` | 登录态（Cookie，**请勿分享**） |
| `%LOCALAPPDATA%\Inferry\canvas-deadlines.ics` | 导出的截止日历 |
| `%LOCALAPPDATA%\Inferry\sync.log` | 日志（约 1 MB 轮转，保留 3 份） |
| `%LOCALAPPDATA%\Inferry\updates\` | 更新包临时目录，可随时清理 |
| `<课程根目录>` | 课程文件（默认 `%USERPROFILE%\CanvasCourses`，由你指定） |

### 从 1.3.4 升级到 2.0.0

- **先确认自己在 1.3.4**：1.3.2 及更早版本的更新器不认识新程序名，需要手动下载 zip 覆盖一次。
- **数据目录迁移**：`%LOCALAPPDATA%\CanvasHelper` 会在首次启动时一次性迁移到 `%LOCALAPPDATA%\Inferry`，登录态与课程配色跟着走；两个目录都存在时以新目录为准，不会覆盖。
- **计划任务**：旧的 `CanvasHelper-*` 任务会自动清理，并按新程序路径重建。
- **桌面快捷方式**：旧的 `CanvasHelper.lnk` 会失效，请到 设置 → 创建桌面快捷方式 重建。
- **命令行**：`canvas-helper` 更名为 `inferry`，脚本与文档里的命令请一并替换。
- **回滚**：如需退回 1.3.4，把 `%LOCALAPPDATA%\Inferry` 改名或复制回 `%LOCALAPPDATA%\CanvasHelper`，再安装 1.3.4。

## 常见问题

**Q：双击 exe 没反应，或提示「缺少依赖 / 安装不完整」？**

绿色版一般是解压不完整或被安全软件拦了部分文件：重新完整解压一次（不要直接在压缩包里运行）。源码版通常是没执行 `python -m pip install .`；控制台运行 `python -m inferry --version` 能看到真实报错。

**Q：Windows 提示「已保护你的电脑」/ 杀毒软件报毒怎么办？**

发布包没有商业代码签名，PyInstaller 单目录结构又容易被启发式误判。可在提示里点「更多信息 → 仍要运行」，或把程序目录加入杀毒软件白名单；确认下载来源是本仓库 Releases。

**Q：提示「没有可用的浏览器」？**

程序优先用系统自带的 Microsoft Edge。精简系统或非 Windows 环境里 Edge 可能不存在，两条路任选：装回 Edge，或在设置页点「安装 Chromium」（等价于 `inferry install-browser`，约 150 MB）。

**Q：登录一直超时 / 计划任务没跑，日志里说登录过期？**

登录窗口只负责取会话，超时一般是 SSO 页面没走完（例如还要二次验证、点了取消、或学校要求连 VPN）。重新点「登录 / 刷新课程」即可。后台任务发现会话过期时：允许弹窗且有可见桌面会话时会弹一次登录窗口；否则只写状态并让本次任务退出码为 `2`，打开 GUI 后顶栏会提醒。若你希望后台永远不弹窗，把配置里的 `auth.popup_on_expiry` 改成 `false`。

**Q：同步完成了，但某门课的文件明显不全？**

Canvas 对学生账号的权限限制很常见：课程级文件索引、逐文件夹列举都可能返回 403，隐藏/锁定文件也读不到。Inferry 会从模块条目、页面正文、作业描述、公告/讨论里尽可能补齐，但拿不到的内容不会绕过权限获取。可先看 `%LOCALAPPDATA%\Inferry\sync.log` 里的 403/警告，再对照浏览器里能看到的页面确认。

**Q：课程文件夹对不上，每次同步都新建一个重复文件夹？**

说明本地文件夹名与 Canvas 的课程代码没匹配上。检查两点：本地文件夹是否以课程代码开头（`CS5187 - ...`）；学校的课程代码是否不是「字母 + 3~5 位数字」的形态。后者可在设置页「课程代码正则」写一个正则（第一个捕获组优先）。也可以在配置的 `course_map` 里直接把课程 id 钉到某个文件夹名。

**Q：待办里的截止时间差了几个小时？**

时区没配对。设置页「时区」填 IANA 名（如 `Asia/Hong_Kong`、`America/New_York`、`Asia/Shanghai`），留空表示跟随本机系统时区。写错会导致截止显示、过期判定和每周摘要的周界一起偏。

**Q：同步完了，DeskBox 里没有新待办？**

依次排查：① 设置页的 `DeskBox todo.json` / `DeskBox 程序路径` 是否已正确识别（未安装或装在非标准位置时需要手选）；② 后台同步采用「排队」策略时，待办会先进入 `pending_todos.json`，下次打开 Inferry 才写入，也可用 `inferry flush` 立即补写；③ 该作业是否已过期或已完成——两者都不会再写入；④ 日志里是否有 todo.json 解析失败或写入被占用。

**Q：为什么写入待办时 DeskBox 会闪一下、短暂消失？**

DeskBox 运行时不会重新读取被替换的 `todo.json`，所以采用「写副本 → 关闭 → 原子替换 → 立即重启」的流程，停机通常不到 1 秒。不想被打扰可以把后台策略改成「排队」或「跳过」。

**Q：我手动拖好的待办顺序被改了？**

「按截止时间排序」默认开启，会在每次写入时重写 `sortOrder`。到设置页取消该勾选即可保留手动顺序。

**Q：已经完成的作业，为什么又出现了 / 截止时间变了会不会重复提醒？**

已完成记录只存在本地 `state.json` 里：已完成且截止时间没变 → 不再添加；Canvas 上截止时间改动过 → 视为新截止重新提醒；同名同截止的重复项在已有完成记录时会自动清理。若你删过本地数据目录，这些记忆也会一起丢失。

**Q：压缩包下载了却没解压？**

判定规则是保守的：包名含 `data` / `train` 等关键词、或包内没有讲义/代码类文件，就按**数据包**原样保留（避免把数据集铺满课程目录）。可以调小配置 `archives.data_name_hints`，或手动解压。另外：`.rar` / `.7z` 需要外部工具，标准库无法处理；解压总量超过 2 GiB 会主动放弃（防 zip 炸弹）；加密包会标注失败且不再重试。

**Q：我的学校不在院校清单里，能用吗？**

能。清单只是省去猜域名的麻烦：在「选择院校」窗口里直接填 `canvas.example.edu` 即可，程序会自动补 `https://` 并去掉 `/login` 之类的路径。清单本身会在线合并 Instructure 官方目录，缓存 30 天。

**Q：程序会把我的数据上传到哪里吗？**

不会上传到作者服务器。网络请求只发生在本校 Canvas 站点、GitHub（检查更新、拉取院校目录）以及你主动下载的外部链接（如讨论区里的 GitHub / Drive 文件）。登录凭据只保存在本机 `session.json` 与浏览器 profile 中——**不要**把数据目录或日志原样发给别人，里面可能含 Cookie、课程名与文件路径。

**Q：一键清理会不会删掉登录态？**

默认不会：默认只清同步状态、已读标记、导出日历、日志和浏览器缓存；登录态（`session.json` 与 Cookie）与排队待办需要额外勾选，清理前会显示每一项的体积与影响。

**Q：怎么彻底卸载？会不会删我的课程文件和待办？**

绿色版双击 zip 根目录的 `uninstall.bat`；源码版执行 `inferry uninstall`。默认删除程序目录、`%LOCALAPPDATA%\Inferry`、两个计划任务与桌面快捷方式；加 `--keep-data` 可保留配置与登录态。**课程文件夹和 DeskBox 待办永远不会被删除**——需要的话请自行清理。

**Q：支持 macOS / Linux 吗？**

不支持。计划任务、DeskBox 集成、快捷方式、路径习惯都面向 Windows；其他平台上即使能启动界面，也不保证可用。

**Q：更新检查失败、或公司网络连不上 GitHub？**

更新检查是「尽力而为」：失败会自动降级、写一次尝试时间，默认 24 小时内不再重试，不影响同步与待办。要新版本时可到 Releases 页手动下载覆盖（源码版直接 `git pull` 后重新 `pip install .`）。

## 相关项目：DeskBox

[**DeskBox**](https://github.com/Tianyu199509/DeskBox)（[官网](https://deskbox.fun)）是一款免费开源的 Windows 桌面整理工具，用 WinUI 3 小组件把桌面图标、文件与待办放到桌面上，项目以 GPL-3.0 发布。

两个项目的关系是**单向、文件级的协作**：

- Inferry 只负责把 Canvas 的截止时间「搬」进 DeskBox 的待办小组件；待办的展示、提醒、勾选完成都由 DeskBox 自己完成。
- 数据格式是 DeskBox 小组件目录下的 `todo.json`（`version` / `items`，含 `text`、`dueDate`、`colorMarker`、`sortOrder`、`attachments` 等字段）。
- Inferry 首次运行会扫描 `%LOCALAPPDATA%\DeskBox\data\widgets\*\todo.json`，选条目最多的那个，并在常见安装位置寻找 `DeskBox.exe`；也可以在设置页手动指定这两个路径。
- 写入时 Inferry 会合并而非覆盖：同一条待办按 Canvas 链接或「标题 + 截止时间」去重，你自建的待办只会被按需改色/重排，不会被删除。
- 两个项目彼此独立：不装 DeskBox，Inferry 依然可以同步文件、导出 `.ics`、查看通知与成绩，只是不会写入待办。

使用建议：

- 写入前先退出 DeskBox 的待办编辑状态，避免两边同时改同一个 `todo.json`；程序本身也会用「关闭 → 替换 → 重启」保证一致性。
- 如果你是 DeskBox 的重度用户、手工维护了大量待办，建议先备份 `todo.json`，并关闭「按截止时间排序」以免打乱你的顺序。
- DeskBox 升级后若待办数据结构有变，请以 DeskBox 的发布说明为准；Inferry 侧遇到解析不了的 `todo.json` 会记录错误并跳过写入，不会清空你的待办。
